# P1: urna logs to a queryable lake, on a sample

Goal: a sample run (all of Roraima plus about 1% of sections nationwide) turns urna logs into
`br_tse_urna_logs.eventos`, loads section turnout, and every collected section passes the check
"votes in the log on election day = comparecimento". Same code later runs as a Kubernetes Job.

Facts this plan builds on (checked 2026-10-27):
- Section list: `{base}/{pleito}/config/{uf}/{uf}-p00{pleito}-cs.json`, shape `abr[].mu[].zon[].sec[]`.
  A section entry is `{ns, da, ha}`, `{ns, nsa: [...], da, ha}` (principal of an aggregation) or
  `{ns, nsp}` (aggregated into section nsp; it has no files, aux.json is 404). Roraima: 1627
  entries, 108 aggregated.
- Section index `aux.json`: `hashes[].arq[] = {nm, tp}`; tp "log" is `<name>-log.jez`, a ZIP with
  `logd.dat` (latin-1, tab-separated: `dd/mm/yyyy hh:mm:ss`, level, urna id, component, message,
  16-hex authenticator). More than one hash can exist (replaced urna); read all of them.
- The round 2 log also holds round 1 and setup days; filter by election date.
- Check passed on one section (RR 03085/0008/0001): round 2 log 187 = comparecimento 187,
  round 1 log 217 = 217.
- Turnout per section, both rounds: CKAN `detalhe_votacao_secao_2026.zip`, member
  `detalhe_votacao_secao_2026_BR.csv` (president) or `_<UF>.csv` (state offices).
- TSE limit is about 100 requests/s per IP. Pods share an egress IP: one global limiter.

## Contracts (fixed; do not change without the lead)

- `brasildb/config.py`: `Settings`, `load()`, `ELECTIONS`, `UFS`.
- `brasildb/tse/paths.py`: `SectionKey`, `cs_url`, `aux_url`, `file_url`.
- `catalog.yaml`: every table, its columns, types, partition and keys.
- Fixtures in `tests/fixtures/` are real TSE files (Roraima, round 2).

## Tasks (parallel; each owns only its files; no commits; run its own tests with `uv run pytest`)

### T1 sections: `brasildb/tse/sections.py`, `tests/test_sections.py`
- `@dataclass(frozen=True) SectionEntry(key: SectionKey, principal: str | None, aggregated: tuple[str, ...])`
- `parse_cs(cs: dict, uf: str) -> list[SectionEntry]`: one entry per `sec` item. `principal` = `nsp`
  when present, else None. `aggregated` = tuple of `nsa` (or empty). Codes zero-padded strings.
- `sample_sections(by_uf: dict[str, list[SectionEntry]], fraction: float, seed: int, full_ufs: set[str]) -> list[SectionEntry]`:
  every entry of `full_ufs`; for other states a random `fraction` of principal sections
  (`principal is None`), deterministic for a seed, plus the aggregated entries that point to the
  sampled principals. Sorted by key.
- Tests on `cs_rr_3221.json`: 1627 entries, 108 with principal, municipality 03123 zone 0007
  section 0012 has aggregated ("0120",), section 0120 has principal "0012"; sample is deterministic.

### T2 fetch: `brasildb/tse/fetch.py`, `tests/test_fetch.py`
- `RateLimiter(rps: float)`: `async acquire()`; one shared instance limits all requests.
- `@dataclass SectionResult(entry: SectionEntry, status: str, logs: list[tuple[str, str, bytes]], erro: str | None)`;
  status `ok | agregada | sem_log | erro`; logs = (hash, file name, bytes).
- `async fetch_section(client: httpx.AsyncClient, limiter, base: str, election: Election, entry) -> SectionResult`:
  aggregated entry: status `agregada`, no request. Else GET aux.json; 404 gives `sem_log`; collect
  every `tp == "log"` (or name ending `-log.jez`) across all hashes, GET each. Retry timeouts and
  5xx up to 5 times with backoff 1, 2, 4, 8 s; 404 is not retried. Any other failure: `erro` with message.
- `StateStore(path: str)`: SQLite. `done(ano, turno) -> set[SectionKey]` (status ok or agregada or
  sem_log); `record(ano, turno, result)`. Creates its table if missing.
- `async collect(settings: Settings, election: Election, entries: list[SectionEntry], on_result: Callable[[SectionResult], None]) -> dict[str, int]`:
  skip done entries, run `settings.concurrency` workers sharing one limiter at `settings.rps`,
  call `on_result` then `record` for each, return counts by status.
- Tests with `respx` (no network): ok section using fixtures, aggregated, aux 404, 503 then ok,
  two hashes give two logs, resume skips done sections, limiter spacing.
- Imports `SectionEntry` from `brasildb.tse.sections` (T1). If T1 is not there yet, write against the
  contract above.

### T3 log parser: `brasildb/tse/logparse.py`, `tests/test_logparse.py`
- `extract_logd(jez: bytes) -> bytes`: the `logd.dat` member (case-insensitive name).
- `EVENT_TYPES`: ordered list of `(tipo_evento, compiled regex)`; regex group 1, if any, is `valor`:
  `voto_computado` "O voto do eleitor foi computado"; `habilitacao` "Tipo de habilitação do eleitor \[(.+?)\]";
  `voto_confirmado` "Voto confirmado para \[(.+?)\]"; `eleitor_habilitado` "Eleitor foi habilitado";
  `inicio_aplicacao` "Iniciando aplicação - (.+)"; `urna_ligada` "Urna ligada em"; `correcao`
  "Eleitor corrigiu"; `digital_capturada` "Capturada a digital".
- `parse_logd(data: bytes) -> Iterator[dict]`: decode latin-1, one dict per line with keys
  `linha, data_hora (datetime), nivel, id_urna, componente, mensagem, autenticador, tipo_evento, valor`.
  Skip lines that do not have 6 tab fields or a valid timestamp.
- `parse_logd_stats(data: bytes) -> tuple[list[dict], int]`: the rows plus the number of skipped lines.
- Tests on `o03221rr0308500080001-log.jez`: `voto_computado` on 2026-10-25 = 187, on 2026-10-04 = 217;
  first row is 2026-09-23 08:11:57; `habilitacao` valor includes "biométrica".

### T4 TSE CSV loaders: `brasildb/tse/csv_tables.py`, `tests/test_csv_tables.py`
- `fetch_zip_member(url: str, member: str, dest_dir: str) -> Path`: stream the ZIP with httpx to
  `dest_dir`, extract only `member`, return its path; skip download if the member already exists.
- `read_detalhe_votacao_secao(path: str) -> pyarrow.Table` with exactly the catalog columns and types
  of `br_tse_eleicoes.detalhes_votacao_secao`. Use DuckDB `read_csv(encoding='latin-1', delim=';', header=true, all_varchar=true)`
  then cast. `#NULO`, `#NULO#`, `#NE`, `-1`, `-3` become NULL in text columns. `sigla_uf` upper case.
- `read_municipio(path: str) -> pyarrow.Table` for `br_bd_diretorios_brasil.municipio`.
- Tests on `detalhe_votacao_secao_2026_BR_rr_sample.csv` (both rounds) and `municipio_tse_ibge_rr.csv`:
  RR 03085/0008/0001 turno 2 comparecimento 187, turno 1 217; codes zero-padded; 15 RR municipalities.

### T5 lake: `brasildb/lake.py`, `tests/test_lake.py`
- `load_catalog() -> dict` from `catalog.yaml` at the repo root.
- `write_table(lake: str, dataset: str, table: str, data: pyarrow.Table, basename: str) -> None`:
  hive partitions from the catalog `partition` list; file name `{basename}-{i}.parquet`; writing the
  same basename again replaces those files (idempotent). Validate column names against the catalog.
  Local paths now; `s3://` through `pyarrow.fs.S3FileSystem` with `AWS_*` / `BRASILDB_S3_ENDPOINT` env.
- `connect(lake: str, database: str = ":memory:") -> duckdb.DuckDBPyConnection`: for each catalog table
  with files, `CREATE SCHEMA <dataset>` and `CREATE VIEW <dataset>.<table>` over
  `read_parquet('<lake>/<dataset>/<table>/**/*.parquet', hive_partitioning=true, union_by_name=true)`.
  For `s3://`, load `httpfs` and create a secret from env.
- Tests in `tmp_path`: write, rewrite same basename, query through views, column validation error.

### T6 SQL: `sql/views/*.sql`, `sql/checks/*.sql`, `brasildb/sqlrun.py`, `tests/test_sql.py`
- `sqlrun.apply(con, folder)`: run every `.sql` in name order. Files use only schema-qualified catalog
  tables and other views.
- `sql/views/00_eleicoes.sql`: `main.eleicoes(ano, turno, id_pleito, data)` from VALUES matching
  `config.ELECTIONS`.
- `sql/views/10_fuso_municipio.sql`: `main.fuso_municipio(ano, turno, sigla_uf, id_municipio_tse, fuso)`:
  from voto_computado on election day, median of each section's first vote time; offset = round((median minutes - 480) / 60);
  fewer than 3 sections falls back to the state default (AC -2; AM, MT, MS, RO, RR -1; others 0).
- `sql/views/20_votos_hora.sql`: `main.votos_hora(ano, turno, sigla_uf, id_municipio_tse, zona, secao, hora_local, hora_brasilia, votos)`.
- `sql/checks/comparecimento.sql`: `main.check_comparecimento(..., votos_log, comparecimento, status)`
  per section; comparecimento = max over cargos; status `ok | diferente | sem_log | sem_csv`.
- `sql/views/30_votos_hora_uf.sql`: roll-up by state and Brasília hour.
- Tests: build the catalog tables in an in-memory DuckDB with synthetic rows (no Parquet), apply
  folders, assert counts, time zone fallback and each check status.
