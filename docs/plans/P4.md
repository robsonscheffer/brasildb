# P4: "O Brasil votando" v2 on real data, then the publish pass

Goal: the v2 walk (P3, PR #20) runs on the round 2 lake instead of the mock, every number on
the page traces to one SQL query, and the page goes to `/` after a copy and publish review.
No claim about the result; no side; no fraud talk.

Facts this plan builds on (checked 2026-10-29):
- The walk reads five data shapes under `docs/site/v2/data/`: `urna.json`, `curiosidades.json`,
  `cidades/<UF>.json`, `secoes/<UF>/<zona>.json`, `chegada.json`, plus v1's `towns.json`,
  `totals.json`, `borders.json`, `frames.png`. Contracts in P3 "Data". Every file carries
  `mock`; the page shows "dados simulados" while any loaded file is a mock.
- `scripts/site_v2_mock.py` writes the mock. Town names, votes and the national curve in it
  are real (from v1); places, seconds, closes, arrivals and log lines are simulated.
- The lake has `main.secao_dia` (one row per section: abertura, primeiro_voto, ultimo_voto,
  encerramento, votos, quedas, min_bateria, contingencia, n_logs, modelo), `main.votos_minuto`
  (town x minute, Brasília), `main.fuso_municipio`, `br_tse_eleicoes.detalhes_votacao_secao`
  (aptos per section) and `br_tse_urna_logs.eventos` (every log line). `data/raw/cs/` has the
  TSE arrival time `ha` of each section's result.
- The page hard-codes a few numbers in HTML: 127.854.844 (h1, meta, card label), 08:00:19
  and Niterói in the hook, 19:06 in the meta. They are not read from data.

## Decisions

- D1 One script, `scripts/site_v2_data.py`, writes every v2 file with `"mock": false`, from
  the DuckDB lake. Same paths and shapes as the mock; the page does not change for data.
- D2 Every curiosity carries its SQL in the `sql` field and its value in `valor`. A fact the
  query does not support is rewritten to what the query says, or dropped. The copy never
  bends to keep a nice line.
- D3 Ties: the 100 millionth vote is the 100.000.000th `voto_computado` row ordered by
  Brasília time, then `sigla_uf`, `id_municipio_tse`, `zona`, `secao`, `linha`. The same order
  resolves the first and the last vote. The page says "entrou" and never "foi".
- D4 Brasília time everywhere on the page; the urna's local clock only on `como.html`.
- D5 The hard-coded numbers become data: the page reads the total, the first vote and the last
  vote from `curiosidades.json` on load, and a check script fails the build when the HTML
  still holds a digit string that is not in the data.
- D6 Publish means the swap in P3 W5 (v2 at `/`, v1 at `/explorar`). It needs Robson's go
  after W8, with the mock pill gone and the `[NEED]` list empty.

## Tasks

### W1 facts (`scripts/site_v2_data.py curiosidades`)
- One function per `id` above, returning value, place with lat/lon (from `municipio`), minute
  and the SQL text. The `texto` is built from the value, never typed by hand in the script.
- A fact whose query changes the claim gets the rewrite in the same PR, with the old line in
  the PR body.
- Done when `curiosidades.json` has every `id` with `sql` set and `mock: false`, and the
  table above has no "verify" left.

### W2 the urna and the first minute (`urna.json`)
- The section of the first vote: its log lines from `eventos` from power-on to the first vote
  (tipo `inicio`, `zeresima`, `urna_pronta`, `eleitor_habilitado`, `voto_computado`), then
  the next votes of that urna.
- `primeiro_minuto`: the real count of votes before 08:01 and up to 160 of them with town,
  state and second, in time order.

### W3 towns and sections (`cidades/<UF>.json`, `secoes/<UF>/<zona>.json`)
- Per town: `votos`, `aptos`, `secoes`, `pico` minute, `metade` minute, `ultimo_voto`,
  `fechamento` (median `encerramento`), `chegada` (median `ha`), `horas` (votes per hour band
  08h to 19h from `votos_minuto`).
- Per section: `abertura`, `primeiro_voto`, `ultimo_voto`, `encerramento`, `votos`, `aptos`,
  `chegada` (`ha`), `fim_log` (the last 8 log lines, close to shutdown). A replaced urna: the
  closing log's lines.
- Sizes: a UF file under 33 KB gzip, a zona file under 10 KB. Report the largest.

### W4 the counting curve (`chegada.json`)
- Sections arrived per minute, national and per state, from `data/raw/cs/`.
- Check on a 1% sample of per-section `aux.json` that `ha` is the first arrival, not the
  last; write the answer on `como.html`.

### W5 the map frames
- Re-encode `frames.png` with a floor so a town with 1 vote/min is not pixel 0, and under
  1 MB. The map after 17:35 must still show the towns in the queue.

### W6 the page reads its numbers (D5)
- `index.html` reads the total, the first and the last vote from the data; the hard-coded
  strings go.
- `scripts/site_v2_check.py`: every digit string of 4 or more digits in the HTML and in every
  `texto` of the data has a source row; prints the ones that do not. Runs in CI with the
  mock and with the real files.

### W7 `como.html` (P3 W3, still open)
- Part 1 the urna's day, term by term. Part 2 sources, method, the 9 mismatched sections,
  the 1.352 sections without a log, the Alto Solimões town list, the half-vote town floor,
  the `ha` answer from W4, the `n_logs` vs `contingencia` choice.

### W8 the publish pass: copy and what the public page needs
One task, one checklist file `docs/plans/P4-publish.md`, each line checked by Robson.
- Copy: every line of the walk through the copywriting skill, then copy-editing; every
  sentence names a place, a minute or a number; no "seguro", no "fraude", no side, no
  candidate; no em-dashes; pt-BR; each term linked to `como.html#<term>`.
- Facts: W1's table, every row read against its SQL by a second person or a second session.
- Public: the mock pill gone (no file with `mock: true`); a per-town OG image or one static
  OG image; share text and card checked on WhatsApp and Instagram; the meta description with
  the real numbers; a line naming the source (TSE open data) and the repo on every fold's
  footer or on the card; `robots` and the page title; the test link format for towns kept.
- Access: reduced motion, screen-reader tables, keyboard walk, 390x844 and 1440x900 and a
  short laptop height, 0 console errors.
- Done when the checklist has no open line and Robson says publish.

### W9 the swap (P3 W5)
- v2 at `/`, v1 at `/explorar`, redirects for town share links, README updated.

## Order

W1 and W4 first (they decide the copy). W2, W3, W5 next, in parallel. W6 when W1 is in.
W7 after W1 and W4. W8 after everything. W9 after Robson's go.

## Rules for every task
- Work in a worktree on a branch from `main`; one PR per task; no merge without a go.
- Test server on a free port from the worktree. Port 8765 serves main; never stop it.
- Commits `type(scope): subject`, at most two body lines.
- The lake path comes from `BRASILDB_DATA`; the script never assumes a laptop path.

## Not in scope
- Any statement about who won, vote shares over time, or the result (P3 D13).
- Round 1, video, sound, English, the Apuração page.
